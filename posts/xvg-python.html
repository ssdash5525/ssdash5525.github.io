GROMACS writes most analysis output in .xvg format — which is essentially plain text with metadata headers. It looks simple, but in practice people either plot it incorrectly or spend too much time manually cleaning it.

This note shows a clean, reproducible way to read .xvg files in Python, handle multiple datasets, and produce publication-quality plots without hacks.

1. What is inside an .xvg file?

A typical .xvg file contains:

  • Comment lines starting with #
  • Metadata lines starting with @
  • Numerical data columns (time, observable, etc.)
# This is a comment
@    title "RMSD"
@    xaxis  label "Time (ps)"
@    yaxis  label "RMSD (nm)"
0.0   0.12
1.0   0.15
2.0   0.14
Key point: You must ignore lines starting with # and @ when loading data.

2. Minimal parser (clean and reliable)

The simplest robust approach is to filter metadata lines and load the rest using numpy.

import numpy as np

def read_xvg(filename):
    data = []
    with open(filename) as f:
        for line in f:
            if line.startswith(("#", "@")):
                continue
            data.append([float(x) for x in line.split()])
    return np.array(data)

Usage:

data = read_xvg("rmsd.xvg")
time = data[:, 0]
rmsd = data[:, 1]

3. Plotting properly (not the default ugly plot)

Most quick plots are unreadable. A few small changes improve clarity significantly.

import matplotlib.pyplot as plt

plt.figure(figsize=(6,4))
plt.plot(time, rmsd, linewidth=1.5)

plt.xlabel("Time (ps)")
plt.ylabel("RMSD (nm)")
plt.title("RMSD vs Time")

plt.tight_layout()
plt.show()
Tip: Always set axis labels explicitly — do not rely on memory of what the columns mean.

4. Handling multiple datasets (very common case)

Some GROMACS outputs (e.g. RDF, energy components) contain multiple columns.

data = read_xvg("rdf.xvg")

r    = data[:, 0]
g_r1 = data[:, 1]
g_r2 = data[:, 2]

plt.plot(r, g_r1, label="Dataset 1")
plt.plot(r, g_r2, label="Dataset 2")

plt.legend()
plt.xlabel("r (nm)")
plt.ylabel("g(r)")
plt.show()

5. Smoothing noisy data (optional but useful)

MD data is often noisy. A simple moving average helps reveal trends.

def moving_average(x, window=10):
    return np.convolve(x, np.ones(window)/window, mode='valid')

smooth_rmsd = moving_average(rmsd, window=20)

plt.plot(time[:len(smooth_rmsd)], smooth_rmsd)
plt.xlabel("Time (ps)")
plt.ylabel("RMSD (nm)")
plt.show()
Warning: Smoothing changes the data. Use it only for visualization, not for quantitative analysis.

6. A cleaner alternative (pandas)

If you prefer pandas, you can skip manual parsing:

import pandas as pd

df = pd.read_csv(
    "rmsd.xvg",
    comment='@',
    delim_whitespace=True,
    header=None
)

df = df[~df[0].astype(str).str.startswith('#')]

time = df[0].astype(float)
rmsd = df[1].astype(float)

7. What most people do wrong

  • Plotting without removing metadata → crashes or wrong data
  • Not labeling axes → unusable figures
  • Over-smoothing → misleading trends
  • Copy-pasting data manually → not reproducible

Conclusion

The .xvg format is simple, but treating it properly makes your workflow reproducible and your figures publication-ready. Once this pipeline is set up, every new analysis becomes trivial.
